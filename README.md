# image-to-point-curve
画像の輪郭を抽出し、Point Curve形式のテキストファイルに変換するWebツール。白黒・カラー画像に対応。 / A web tool that extracts contours from monochrome and color images and converts them into Point Curve text files.

## 公開ページ

https://tarosay.github.io/image-to-point-curve/

画像の処理はすべてブラウザ内で行います。画像がサーバーへ送信されることはありません。スマートフォンでも使えます。

## 使い方

1. 画像（PNG / JPEG / WebP）を画面上部の枠にドラッグ＆ドロップするか、枠をタップして選択します。
2. 画像の種類（白黒・線画／カラー）が自動で選ばれ、抽出した輪郭がプレビューに表示されます。
3. 必要に応じて右側（スマートフォンでは下側）のパラメータを調整します。
4. 「point curve (.txt) をダウンロード」を押して TXT を保存します。DXF が必要なときは「DXF (.dxf) をダウンロード」を押します。
5. DesignSpark Mechanical で TXT を Point Curve として読み込みます。DXF は DXF を読み込める CAD で開きます。

### 調整できる項目

| 項目 | 内容 |
| :--- | :--- |
| 読み込み方式（Polyline） | True：折れ線（初期値）／False：スプライン補間 |
| サイズの決め方 | **円に収める**（初期値）：すべての輪郭の点を囲む最小の円の直径を指定（初期値 78.5 mm）。原点は円の中心<br>**画像全体の幅・高さを指定**：余白を含む画像全体の縦横比を維持。原点は画像の左下 |
| 画像の種類 | 白黒・線画：明るさで二値化（しきい値は自動または手動、反転も可）<br>カラー：最大色数と色の判定許容差で色をまとめ、出力する色をチェックで選択（画像の縁に最も多い色を背景として初期状態で除外） |
| 隣り合う色の境界の出力 | **重複を減らす**（初期値）：隣り合う色の境界が二重に出力されないよう、出力する輪郭を選ぶ（下の「重複の削減」を参照）<br>**従来の方式**：出力する色ごとに、その色の領域の輪郭をすべて出力 |
| 境界の中間色を隣の色に吸収する | カラーで重複を減らす方式のときに有効（初期値：オン）。2色の境目のにじみが別の色として抽出された、幅2画素以下の細い領域を隣の色に塗り替える |
| 簡略化の許容誤差 | 小さいほど元の形に忠実で点数が増え、大きいほど点数が減る |
| なめらかさ | 画素のギザギザをならす回数。大きくすると角が丸くなる |
| 処理解像度 | 画像をこの長辺サイズに縮小してから輪郭を抽出（拡大はしない） |
| 除去する最小面積 | これより小さい領域（点状のゴミ・小さな穴）を除去。重複を減らす方式では隣の色に吸収する |
| 細かな凹凸の除去 | 3×3 画素の多数決で境界を整える回数。細い線は消えることがある |

座標はいずれも mm 単位、Y 軸は上向きです。

### プレビューと比較表

- 「元画像を重ねる」「点を表示」「塗りつぶし」「外接円」「重複箇所を赤で表示」で表示を切り替えられます。
- プレビューの下の表に、従来の方式と重複を減らす方式の輪郭数・点数・重複区間の長さ（mm）を並べて表示します。
- 重複区間の長さは、別の色の輪郭の線から 1.2 px（処理解像度）以内を通る部分の長さを mm に換算した目安です。同じ色の輪郭どうし（細い線の表と裏など）は数えません。

## 重複の削減

カラー画像を色ごとに輪郭抽出すると、隣り合う2色の境界が両方の色から1回ずつ出力され、同じ位置に輪郭が重なります。重複を減らす方式では次のように処理します。

1. 色の画像を「領域」と「領域の境界線」に分け、境界線を3色以上が接する点で区間に分けます。区間は一度だけ平滑化・簡略化するので、共有する境界は同じ座標になります。
2. すべての出力対象の境界線が少なくとも1回出力され、両側とも出力されて重複する区間が最も短くなるように、出力する領域を選びます。
3. 選んだ領域の外周と穴を出力します。出力はすべて閉曲線です（DesignSpark Mechanical は開いた Point Curve を読み込めないため）。

閉曲線のまま必要な境界をすべて残すため、3色以上が接する部分などでは重複が残る場合があります。


## 出力形式

```
Polyline=True
0 10.0000 20.0000
0 15.0000 25.0000
0 20.0000 20.0000
0 10.0000 20.0000

0 30.0000 40.0000
...
```

- 各行は `0 X Y`（mm、小数4桁）
- 外周・内側の穴を含め、複数の閉曲線を空行で区切って出力
- 各閉曲線の最後に始点を再出力
- 改行コードは CRLF

### DXF

- 形式は DXF R12（AC1009）の ASCII。古い CAD でも読めるよう、各輪郭を閉じた `POLYLINE`（頂点は `VERTEX`）として出力
- 座標は TXT と同じ（mm、Y 軸上向き、小数4桁）。単位は `$INSUNITS = 4`（mm）を指定
- 画層：白黒は `CONTOUR`、カラーは出力する色ごとに `COLOR_01`、`COLOR_02`…（番号は「出力する色」の「色 n」と同じ）。画層の色は元の色に近い AutoCAD の基本色
- 折れ線として出力するため、読み込み方式（Polyline）の設定は DXF には影響しない
- 改行コードは CRLF

## ファイル構成

| パス | 内容 |
| :--- | :--- |
| `docs/index.html` | 画面 |
| `docs/style.css` | スタイル |
| `docs/app.js` | 画像の読み込み、色の判定、従来の方式の輪郭抽出、出力、画面の処理 |
| `docs/topology.js` | 重複を減らす方式（領域と境界線の区間、出力する領域の選択、閉曲線の組み立て）と重複区間の測定 |

ビルドや外部ライブラリは使っていません。GitHub Pages では、リポジトリの Settings → Pages で、main ブランチの `/docs` フォルダを公開元に設定します。

手元で確認するときは、`docs` フォルダをローカルの Web サーバーで配信してブラウザで開きます。

```bash
python -m http.server 8000 --directory docs
```
